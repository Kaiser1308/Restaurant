# Day 29-30: Frontend UX Polish + Backend Unit Tests

## Purpose

Week 5 Day 29-30 of Phase 1. Day 29 polishes all frontend pages to production UX quality. Day 30 adds xUnit unit tests for backend business rules.

## Day 29: Frontend UX Polish

### Scope

Audit all pages and components. Fix every missing UX pattern consistently.

### 1. Error Toasts on Mutations

Every `useMutation` must have `onError` that shows a Toast with the error message.

Pages to audit:

| Page | Mutations to check |
|------|-------------------|
| LoginPage | login mutation (already has toast) |
| WaiterOrderPage | addItem, updateItem, cancelItem, sendToKitchen |
| CashierPaymentPage | payOrder |
| BillDetailPage | voidBill |
| TablesManagementPage | createTable, updateTable |
| MenuManagementPage | createCategory, createMenuItem, updateAvailability, uploadImage, deleteImage |

Convention: each page already manages `toastMessage` state + renders `<Toast>`. Ensure all mutations use the existing pattern:

```tsx
const mutation = useMutation({
  mutationFn: ...,
  onSuccess: ...,
  onError: (err) => setToastMessage({ type: 'error', message: err.message }),
})
```

### 2. Disable Double-Click on Mutation Buttons

Every `<Button>` that triggers a mutation must have `disabled={mutation.isPending}`.

Audit all mutation buttons across all pages. Add `disabled` prop where missing.

| Page | Empty scenario | Status |

## Day 30: Backend Business Rule Unit Tests

### Scope

Create xUnit test project. Write 8 unit tests for critical business rules using Moq mocks.

### Test Project Structure

```
tests/
└── Restaurant.Api.Tests/
    ├── Restaurant.Api.Tests.csproj
    ├── Services/
    │   ├── OrderServiceTests.cs
    │   ├── BillServiceTests.cs
    │   ├── PrintJobServiceTests.cs
    │   └── AuthServiceTests.cs
    └── PermissionServiceTests.cs
```

### Dependencies

- xUnit
- Moq
- FluentAssertions (optional, for readable assertions)

### Test Cases

#### OrderService Tests (3)

1. **CreateOrderAsync_DuplicateActiveOrder_ThrowsConflictException**
   - Setup: mock IOrderRepository.GetActiveOrderByTableAsync returns existing order
   - Act: call CreateOrderAsync
   - Assert: throws ConflictException

2. **CancelOrderItemAsync_SentItem_ThrowsBusinessException**
   - Setup: mock IOrderItemRepository returns item with status SentToKitchen
   - Act: call CancelOrderItemAsync
   - Assert: throws BusinessException (cannot cancel sent item)

3. **CancelOrderItemAsync_EmptyReason_ThrowsValidationException**
   - Setup: mock IOrderItemRepository returns Pending item, empty reason
   - Act: call CancelOrderItemAsync with reason = ""
   - Assert: throws validation error

#### BillService Tests (2)

4. **PayOrderAsync_CreatesBillItemSnapshots**
   - Setup: mock order with items, mock IBillRepository, ITenantContext
   - Act: call PayOrderAsync
   - Assert: BillItems contain correct ItemNameSnapshot, UnitPriceSnapshot, Quantity, LineTotal

5. **VoidBillAsync_NonOwner_ThrowsForbiddenException**
   - Setup: mock IPermissionService.CanVoidBill returns false (Cashier role)
   - Act: call VoidBillAsync
   - Assert: throws ForbiddenException

#### PrintJobService Tests (1)

6. **CreatePrintJobAsync_DuplicatePrintKey_ThrowsConflictException**
   - Setup: mock IPrintJobRepository.GetByPrintKeyAsync returns existing job
   - Act: call CreatePrintJobAsync with same printKey
   - Assert: throws ConflictException

#### BillService Sequence Test (1)

7. **PayOrderAsync_BillNumberSequence_IncrementsCorrectly**
   - Setup: mock IBillNumberSequenceRepository, simulate FOR UPDATE lock
   - Act: call PayOrderAsync
   - Assert: BillNumber format is {yyyyMMdd}-{D4}, sequence increments

#### AuthService Tests (1)

8. **RefreshTokenAsync_ValidToken_RotatesToken**
   - Setup: mock IAuthRepository.GetRefreshTokenByHashAsync returns valid token
   - Act: call RefreshTokenAsync
   - Assert: old token is revoked, new refresh token is created and returned

### Mock Strategy

- Mock interfaces: `IOrderRepository`, `IBillRepository`, `IOrderItemRepository`, `IPrintJobRepository`, `IAuthRepository`, `IAuditLogRepository`, `IPermissionService`, `ITenantContext`, `IBillNumberSequenceRepository`
- Use `TenantContext` with test values: TenantId, UserId, Role set via test setup
- Services throw exceptions for business errors — tests assert exception type and message
