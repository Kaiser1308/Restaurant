# i18n Implementation Design for Restaurant POS Web

**Date:** 2026-04-30
**Status:** Approved Design
**Phase:** Phase 1 - Foundation & Language Switcher

---

## 1. Overview

Implement English-Vietnamese language support for the Restaurant POS web app with Vietnamese as default language and English as fallback. Use i18next with namespace-by-feature architecture.

**Target Languages:**
- Vietnamese (`vi`) - default language
- English (`en`) - fallback language

**Goals:**
- No page reload when switching languages
- Auto-detect browser language (en-US → en, others → vi)
- Persist language choice in localStorage
- Support Vietnamese business domain terminology

**Non-Goals (Phase 1):**
- No i18n for API responses (backend remains Vietnamese)
- No i18n for print-agent
- No Zustand or SignalR integration (deferred)

## 3. Component Design

### LanguageSwitcher Component

**Location:** `apps/web/src/components/LanguageSwitcher.tsx`

**UI Design:**
- Dropdown selector with language display names: "Tiếng Việt" and "English"
- No emoji flags - plain text for cross-platform compatibility
- Positioned in all three layouts (WaiterLayout, CashierLayout, OwnerLayout)
- Top-right corner for desktop, integrated in header for mobile

**Component Code:**

```typescript
import { useTranslation } from 'react-i18next'

const SUPPORTED_LANGUAGES = ['vi', 'en'] as const
type SupportedLanguage = typeof SUPPORTED_LANGUAGES[number]

const LANGUAGE_OPTIONS: Record<SupportedLanguage, string> = {
  vi: 'Tiếng Việt',
  en: 'English',
}

const isSupportedLanguage = (value: string): value is SupportedLanguage =>
  SUPPORTED_LANGUAGES.includes(value as SupportedLanguage)

export default function LanguageSwitcher() {
  const { i18n } = useTranslation()
  const resolved = i18n.resolvedLanguage?.split('-')[0] ?? 'vi'
  const currentLang: SupportedLanguage = isSupportedLanguage(resolved) ? resolved : 'vi'

  const handleChange = (e: React.ChangeEvent<HTMLSelectElement>) => {
    const newLang = e.target.value
    if (isSupportedLanguage(newLang)) {
      i18n.changeLanguage(newLang)
    }
  }

  return (
    <>
      <label htmlFor="language-switcher" className="sr-only">
        Change language
      </label>
      <select
        id="language-switcher"
        value={currentLang}
        onChange={handleChange}
        aria-label="Change language"
        className="rounded-lg border border-[var(--color-outline-variant)] bg-[var(--color-surface-white)] px-3 py-1.5 text-sm font-semibold text-[var(--color-on-surface)] focus:ring-2 focus:ring-[var(--color-primary)]"
      >
        {SUPPORTED_LANGUAGES.map(lang => (
          <option key={lang} value={lang}>
            {LANGUAGE_OPTIONS[lang]}
          </option>
        ))}
      </select>
    </>
  )
}
```


## 4. Locale Formatting

**Location:** `apps/web/src/utils/format.ts`

**Approach:** Use native `Intl` APIs - lightweight, no dependencies, browser-native formatting.

### Hook-Based Format Helpers

```typescript
import { useTranslation } from 'react-i18next'

export function useLocaleFormat() {
  const { i18n } = useTranslation()
  const locale = i18n.language.startsWith('vi') ? 'vi-VN' : 'en-US'

  return {
    formatMoney: (amount: number): string => {
      return new Intl.NumberFormat(locale, {
        style: 'currency',
        currency: 'VND',
        minimumFractionDigits: 0,
        maximumFractionDigits: 0,
      }).format(amount)
    },

    formatDateTime: (date: string | Date): string => {
      return new Intl.DateTimeFormat(locale, {
        dateStyle: 'medium',
        timeStyle: 'short',
      }).format(new Date(date))
    },

    formatDate: (date: string | Date): string => {
      return new Intl.DateTimeFormat(locale, {
        dateStyle: 'medium',
      }).format(new Date(date))
    },

    formatTime: (date: string | Date): string => {
      return new Intl.DateTimeFormat(locale, {
        timeStyle: 'short',
      }).format(new Date(date))
    },
  }
}
```

### Pure Utility (for non-React contexts)

```typescript
export function formatMoney(amount: number, locale: 'vi' | 'en'): string {
  const intlLocale = locale === 'vi' ? 'vi-VN' : 'en-US'
  return new Intl.NumberFormat(intlLocale, {
    style: 'currency',
    currency: 'VND',
    minimumFractionDigits: 0,
    maximumFractionDigits: 0,
  }).format(amount)
}
```

### Usage Example

```typescript
function BillPreview({ totalAmount, paidAt }: { totalAmount: number, paidAt: string }) {
  const { formatMoney, formatDateTime } = useLocaleFormat()

  return (
    <div>
      <p className="text-3xl font-bold">{formatMoney(totalAmount)}</p>
      <p className="text-sm">{formatDateTime(paidAt)}</p>
    </div>
  )
}
```

### Migration Notes

Replace existing formatting calls throughout the codebase:
- `.toLocaleString('vi-VN')` → `formatMoney(amount)`
- Manual date formatting → `formatDateTime(date)` or `formatDate(date)`
- Backend values remain as `number` or ISO date strings - only presentation layer formats

## 5. Migration Strategy

**Approach:** Vertical slice migration by feature module, following the task's 4-batch plan.

### Batch 1: Common + Auth

**Files to migrate:**
- `App.tsx` - Login page, error messages, toast notifications
- `components/` - Button, Input, Modal, StatusBadge, Toast shared labels
- `layouts/` - Logout button, navigation labels

**Translation focus:**
- Labels: "Tài khoản", "Mật khẩu", "Đăng nhập", "Đăng xuất"
- Buttons: "Lưu", "Hủy", "Xác nhận", "Quét QR", "Hỗ trợ"
- Status: "Available", "Occupied", "NeedsPayment", "Closed"
- Common: "Tất cả", "Tìm kiếm", "Xóa lọc"

### Batch 2: Tables + Menu

**Files to migrate:**
- Tables feature components in App.tsx (WaiterTablesPage, CashierTablesPage)
- Menu feature components in App.tsx (OwnerMenuPage)

**Translation focus:**
- Tables: "Bàn", "Sơ đồ bàn", "Tên bàn", "Trạng thái bàn"
- Menu: "Danh mục", "Món ăn", "Giá", "Mô tả", "Tạo danh mục", "Tạo món"
- Status: "Available", "Unavailable"

### Batch 3: Orders + Bills

**Files to migrate:**
- Orders feature in App.tsx (WaiterOrderPage, KitchenPage)
- Bills feature in App.tsx (CashierPaymentPage, BillsListPage, BillDetailPage)

**Translation focus:**
- Orders: "Đơn hàng", "Đang xử lý", "Gửi vào bếp", "Hủy món", "Lý do hủy"
- Bills: "Hóa đơn", "Thanh toán", "Tạm tính", "Tổng cộng", "Số hóa đơn"
- Payment: "Tiền mặt", "QR", "Chuyển khoản", "Xác nhận đã nhận tiền"
- Void: "Void bill", "Lý do void", "Hủy hóa đơn"

### Batch 4: Audit + Reports

**Files to migrate:**
- Audit feature in App.tsx (AuditLogsPage)
- Reports (owner dashboard, kitchen view)

**Translation focus:**
- Audit: "Audit logs", "Hành động", "Loại", "Entity ID", "Người dùng"
- Reports: "Báo cáo nhanh", "Báo cáo", "Lọc theo ngày", "Xuất báo cáo"

## 6. Error Handling Strategy (Phase 1 - MVP)

**Approach:** Display backend messages as-is (Vietnamese), no error code mapping.

**Rationale:**
- Backend already returns Vietnamese error messages
- Reduces complexity and risk in Phase 1
- Focuses effort on UI text migration first
- Error code mapping can be added in future phase when backend standardizes error codes

**Implementation:**

```typescript
// Keep error display as-is in Phase 1
const payOrder = useMutation({
  mutationFn: () => billsApi.payOrder(orderId, paymentType),
  onError: () => setToastMessage('Thanh toán thất bại. Vui lòng kiểm tra order trước khi thử lại.'),
})

// No i18n translation needed for backend errors yet
```

**Future Enhancement (Phase 2+):**
- Backend returns standardized error codes
- Frontend maps codes to i18n keys
- Example: `PAYMENT_FAILED` → `bills.errors.paymentFailed`
